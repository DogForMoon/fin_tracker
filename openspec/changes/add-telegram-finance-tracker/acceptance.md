# Пользовательская приёмка

Автоматический full-gate и независимый verify успешны для версии `a38c7371cb0fe6d8b95dd52a713a1e11f8aa06a0`: 40 тестов, 35 сценариев. Статус пользовательской приёмки: ожидается. Автоматические e2e не заменяют подтверждение пользователя. При отсутствии токена или доступа к Telegram приёмка остаётся ожидающей. Токен вводится локально, его не нужно отправлять в чат.

## Запуск тестового бота

Из корня проекта:

```sh
uv sync --locked --dev
cp .env_example .env
```

В `.env` локально заполнить `BOT_TOKEN` токеном тестового бота и задать `DATABASE_PATH=data/acceptance.sqlite3`. Затем:

```sh
uv run --env-file .env fin-tracker
```

Альтернатива: `uv run --env-file .env python -m fin_tracker`. Запустить только один процесс. В Telegram открыть тестового бота и отправить `/start`. Остановка — Ctrl+C.

## Чек-лист

Проверять на отдельной тестовой базе и тестовом боте. Для каждого пункта сообщить «пройдено» либо фактическое поведение при дефекте.

1. Открыть бота и создать расход «Потратил» на 125 без тегов и комментария. Ожидается одна запись 125,00 ₽, расход, московская дата начала.
2. Создать два тега и доход «Получил» на 125,50 с обоими тегами и комментарием. Ожидается одна запись с точной суммой, обоими тегами и текстом.
3. На сумме попробовать `0`, `-1`, `1,234`, `1e3`, буквы, затем `0,01`. Ошибки оставляют на шаге суммы без записи; 0,01 принимается. Также проверить сумму больше 64-битного диапазона, например `999999999999999999999,99`.
4. На тегах вернуться «Назад», изменить сумму и пройти далее. Выбранные теги и комментарий сохраняются в черновике, дата начала не меняется. С первого шага «Назад» возвращает к выбору типа.
5. Начать операцию, заполнить часть полей и отменить. Записи нет. Начать новую при незавершённой старой: есть уведомление о сбросе, новый ввод начинается заново.
6. Просмотреть операции, изменить тип, сумму и теги, завершить редактирование. Дата начала исходная. Повторить редактирование с отменой: сохранённая запись не меняется.
7. Проверить комментарий: «Далее» без нового текста сохраняет прежний; новый текст заменяет прежний. «Очистить комментарий» оставляет на текущем шаге; после завершения комментария нет. Очистка с отменой редактирования сохраняет исходный текст. При создании ввести текст, очистить и завершить — комментария нет.
8. Попробовать создать тот же тег с другим регистром и пробелами по краям: дубликат отклоняется. Переименовать тег — имя меняется и в старых операциях. Переименование в имя другого активного или архивного тега отклоняется.
9. Удалить тег: бот поясняет архивирование; тег остаётся в старых операциях, но недоступен для нового назначения. Создать его имя снова: сообщение «Тег восстановлен из архива», прежние связи сохранены.
10. Редактировать операцию с архивным тегом: изменение суммы без снятия сохраняет тег. Снять тег — появляется предупреждение; повторно назначить нельзя до восстановления. Отмена сохраняет исходную запись.
11. Удалить свою операцию: её больше нет в просмотре, теги остаются.
12. Несколько раз быстро нажать завершающее «Далее» при создании и редактировании. Создаётся одна запись, редактирование применяется один раз. Нажать старые кнопки завершённого и отменённого диалогов во время нового ввода: новый диалог и данные не меняются.
13. Перезапустить бота после сохранения: записи и теги сохраняются. Перезапустить во время ввода: черновик не записан; старые кнопки не продолжают утраченный диалог.
14. При возможности открыть бота вторым Telegram-пользователем: операции и теги первого недоступны, одинаковые имена тегов независимы.
