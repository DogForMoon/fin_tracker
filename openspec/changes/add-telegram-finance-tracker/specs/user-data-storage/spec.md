## Purpose

Обеспечить постоянное хранение завершённых операций и тегов с разделением пользователей и доступом к данным для будущих аналитических запросов.

## ADDED Requirements

### Requirement: Идентификация и изоляция
Система SHALL распознавать пользователя по Telegram ID и повторно использовать его существующий профиль. Любое чтение, изменение, удаление и назначение тегов MUST ограничиваться владельцем данных.

#### Scenario: Повторное обращение
- **WHEN** пользователь повторно открывает бота
- **THEN** доступны прежние сохранённые данные без создания нового профиля

#### Scenario: Чужой идентификатор
- **WHEN** пользователь отправляет действие с ID чужой операции или тега
- **THEN** данные не раскрываются и не меняются, связь с чужим тегом не создаётся

### Requirement: Постоянство и атомарность
Завершённые изменения SHALL сохраняться в локальной базе и переживать перезапуск. Операция и её связи MUST сохраняться либо изменяться целиком; ошибка записи MUST NOT оставлять частичные данные или сопровождаться сообщением об успехе.

#### Scenario: Перезапуск
- **WHEN** бот перезапускается после успешного сохранения операции
- **THEN** сумма, дата, комментарий и связи с тегами доступны без изменений

#### Scenario: Ошибка записи связей
- **WHEN** сохранение операции с тегами завершается ошибкой
- **THEN** ни операция, ни частичные связи не сохраняются, пользователь получает сообщение об ошибке

### Requirement: Выборки для будущей аналитики
Система SHALL предоставлять выборки завершённых операций пользователя по периоду, типу и тегам, включая исторические архивные теги. Интервал SHALL включать начало и исключать конец; границы дат интерпретируются в Europe/Moscow. При нескольких выбранных тегах SHALL отбираться операции с любым из них без дублирования. Результат SHALL содержать точную сумму в копейках, тип, дату, комментарий и теги. Состав готовых отчётов этим изменением не определяется.

#### Scenario: Несколько совпавших тегов
- **WHEN** одна операция содержит два тега фильтра
- **THEN** операция возвращается один раз

#### Scenario: Границы периода
- **WHEN** запрошен московский день
- **THEN** включаются операции от его начала включительно до начала следующего дня исключительно

#### Scenario: Архивный тег
- **WHEN** выборка фильтруется по архивному тегу владельца
- **THEN** возвращаются прежние операции с этим тегом
