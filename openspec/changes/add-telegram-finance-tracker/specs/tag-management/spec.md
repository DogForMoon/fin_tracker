## Purpose

Позволить каждому пользователю управлять собственными тегами для нескольких операций, сохраняя исторические связи при архивировании и переименовании.

## ADDED Requirements

### Requirement: Собственные уникальные теги
Система SHALL позволять создавать и просматривать теги пользователя. Название MUST быть непустым после удаления пробелов по краям. Уникальность SHALL проверяться в пределах пользователя после удаления крайних пробелов и без учёта регистра, включая архивные теги; отображение SHALL сохранять выбранный регистр.

#### Scenario: Повтор активного названия
- **WHEN** пользователь создаёт « ЕДА », имея активный тег «еда»
- **THEN** новый тег не создаётся и бот сообщает о существующем теге

#### Scenario: Независимые пользователи
- **WHEN** два пользователя создают тег «еда»
- **THEN** каждый получает собственный независимый тег

### Requirement: Архивирование без потери истории
Удаление тега SHALL архивировать его, сохраняя назначение в старых операциях. Архивный тег MUST NOT быть доступен для нового назначения. При удалении система SHALL уведомлять об этом поведении.

#### Scenario: Архивирование
- **WHEN** пользователь удаляет тег, связанный с операциями
- **THEN** старые операции показывают тег, а список доступных для назначения его не содержит

### Requirement: Восстановление по названию
Создание тега с названием архивного тега пользователя SHALL восстанавливать тот же тег с прежними связями. Система MUST явно сообщать «Тег восстановлен из архива».

#### Scenario: Восстановление
- **WHEN** пользователь создаёт название, совпадающее с его архивным тегом по правилам уникальности
- **THEN** восстанавливается прежний тег, новая сущность не создаётся, пользователь получает уведомление

### Requirement: Переименование
Система SHALL позволять переименовывать тег; новое название SHALL отображаться у всех связанных операций. Совпадение с другим активным либо архивным тегом владельца MUST отклоняться без изменения данных.

#### Scenario: Исторические операции
- **WHEN** пользователь переименовывает тег «еда» в «продукты»
- **THEN** все операции с этим тегом отображают «продукты»

#### Scenario: Конфликт
- **WHEN** новое название занято другим тегом пользователя, включая архивный
- **THEN** бот сообщает о конфликте и сохраняет прежнее название

### Requirement: Архивный тег при редактировании операции
Редактирование SHALL сохранять уже присвоенный архивный тег, пока пользователь не уберёт его. При снятии такого тега бот MUST предупредить, что повторное назначение потребует восстановления через создание тега с тем же названием.

#### Scenario: Снятие архивного тега
- **WHEN** пользователь убирает архивный тег из редактируемой операции
- **THEN** бот показывает предупреждение и не предлагает назначить тег заново до восстановления

#### Scenario: Изменение другого поля
- **WHEN** пользователь меняет сумму операции с архивным тегом, не снимая его
- **THEN** архивный тег остаётся связан с операцией
